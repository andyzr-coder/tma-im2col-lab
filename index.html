00 / 先分清对象

卷积的两侧，都要为矩阵乘法做准备。

旧文档中的 weight packing 和 NVIDIA im2col，分别处理不同的输入。

你熟悉的权重侧

权重展开与打包

把 OC、IC、KH、KW 组织成二维权重矩阵，再按硬件要求分块、对齐、重排。旧文档里的 64k1n 属于这一侧。

[OC, IC, KH, KW]→[OC, K]
通常保留每个权重元素；可能增加对齐填充。
这次要理解的输入侧

输入滑窗展开

根据每个输出位置，把卷积窗口需要的输入元素组织成矩阵。重叠窗口会引用同一个输入元素。

X[N, H, W, C]→A[M, K]
M = N×P×Q，K = R×S×C。这里 A 每行对应一个输出位置。
输入矩阵 A[M,K]×权重矩阵 B[K,OC]=输出 Y[M,OC]

02 / 读懂 NVIDIA 的定义
关键在于：什么固定，什么在遍历。

      
1
一次普通 im2col 请求，固定核内偏移。
选定 (r,s)，把它转换成输入空间的偏移 (Δh,Δw)。然后遍历一串窗口基准位置，在每个位置读一段通道。下一次请求可以换偏移、换通道段，或换起始输出位置。
SMEM[i,j] = X[nᵢ, h₀ᵢ+Δh, w₀ᵢ+Δw, c₀+j]
i 遍历 Pixels-per-Column；j 遍历 Channels-per-Pixel。越界时按本例设定补零。
2
Bounding box 限定窗口基准位置的范围。
它不是一个卷积核窗口的大小，也不是搬运元素数量。比如 4×4 输入配 2×2 核、无 padding，窗口左上角只能在 h₀,w₀ ∈ {0,1,2} 中移动。
基准位置 + 核内偏移 → 实际输入位置
核内 offset 改变后，实际访问区域也随之平移。是否读到图像外，要用实际输入坐标再判断。

      
文档字段直观含义最容易混淆的地方

        
tensor coordinates本次从哪个 batch、窗口基准位置、通道开始。空间坐标是 filter base，不等于加完 offset 的取数坐标。

        
im2col offsets当前取卷积窗口里的哪个相对位置。dilation=2 时，核内 r=1 对应 Δh=2。

        
Pixels-per-Column这次遍历多少个空间 / batch 位置。不是 KH×KW；跨行、跨图像后仍继续计数。

        
Channels-per-Pixel每个位置读取多长的通道段。本次元素总数 = 位置数 × 通道数。

        
Traversal stride窗口基准位置沿空间方向怎么前进。与卷积 stride 对应；不负责决定核内 dilation。

        
Global strides输入张量相邻维度的物理字节间隔。这是地址步距，别和卷积步长混在一起。

        
Swizzle调整共享存储的物理排布。与 im2col 的“取哪些输入元素”是两层问题，本例关闭。

      

      
边界字段为什么会出现负数？
Upper-Corner 是相对输入右 / 下端的偏移。
它不是绝对坐标。例如 W=4，最右输入坐标为 3；若窗口基准最大 w₀=2，则 UpperCornerW = 2−3 = −1。Lower-Corner 则相对左 / 上端。
LowerW = −pad_leftUpperW = pad_right − (S−1)×dilation_w用于常规前向卷积、以左上角作为 filter base 的映射。stride 决定范围内哪些位置实际被访问。

      
为什么没有“自动完成整个卷积”？
TMA 负责数据移动。权重的加载、矩阵乘加、偏移和通道块循环、流水线同步仍由 kernel 组织。图中的完整 A 是逻辑上的矩阵，不要求真的先把它全部写入显存。
省掉的究竟是什么？
显式展开通常先写出一个大矩阵，再让 GEMM 读回来。按需展开可以直接准备当前 tile，省去完整中间矩阵的全局存储。输入重用和重复取数仍可能存在，速度取决于缓存、tile 和流水安排。

      
for 每个输出位置块:
    accumulator = 0
    for 每个核内位置 (r, s):
        for 每个输入通道块:
            A_tile = TMA_im2col(起始位置, r, s, 通道块)
            B_tile = load_weights(r, s, 通道块, 输出通道块)
            等待相应数据可用
            accumulator += A_tile × B_tile
    写出当前输出块

    


    
03 / 放回我们的 TMA 项目
新增 im2col，主要改变取数的组织方式。
沿用项目熟悉的“描述符 → 地址生成 → 读返回 → 目标打包 → 完成”结构，逐段看需要什么。

      
项目语境
LD：LPDDR / L2 → L1 Buf
CP：在资料限定的源 / 目标空间之间搬运、重排。
NVIDIA 语境
TMA im2col load：Global memory → Shared memory
两者可以类比数据流，不能直接把接口或存储语义视为相同。

      
版本边界：本页参考现有项目手册中的模块划分，不宣称已经实现 im2col。不同资料中的布局、描述符位宽和折叠参数有变化，这里不把某个旧版本参数当成最终规格。项目 L1 Buf 指片上缓冲，不等于 NVIDIA L1 cache。

      

      

      
方案 A · 软件分解
先用现有搬运命令表达。
软件生成多个窗口 / 行 / 通道段请求，复用现有搬运路径。适合先做功能验证，但指令数量、重复地址计算和边界命令可能增多；是否可行取决于现有指令能否表达所需访问。
方案 B · 增加专用模式
让硬件遍历窗口基准位置。
用描述符给出范围、步长、通道段和像素数；命令给出起点和当前核偏移。硬件完成跨行、跨 batch、越界补零与输出序列组织。需要明确异常、资源占用和完成条件。

      
和 mentor 对齐时，把需求落到这四件事。
  1. 处理输入 activation，还是仍然只是 weight packing？
  2. 源在哪里、写到哪里；要支持哪些维度和数据类型？
  3. 谁循环核内偏移和通道块：软件还是硬件？
  4. 完成怎样定义：请求发完、数据返回，还是目标写入可见？
